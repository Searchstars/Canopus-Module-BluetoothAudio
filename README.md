# Canopus Bluetooth Audio

Exact-target, allocation-free Rust headphone manager module for Xiaomi Band 10 Pro firmware `3.101.030`.

## Status

The full module is implemented and builds to a verifier-clean, size-budgeted ELF:

- portable core (`bluetooth-audio-core`): discovery table (12-entry, dedup), mandatory fresh-pair controller, AVDTP source (including GET_CAPABILITIES fallback and remote control handling), SBC/RTP five-second tone packetizer, bounded Canopus semantic UI — host-tested.
- exact-target backend (`bluetooth-audio-device`, `device` feature): identity guard, asynchronous discovery-stop handoff, separate aggregate/device bond queries, target-only bond removal with NONE confirmation, stock Classic bonding and target callback-policy filter, L2CAP signaling/media, SDP source registration, media tone timer, and RESIDENT irreversible lifecycle. Critical controller/L2CAP/media callbacks deferred by core-lock contention are queued back onto the Bluetooth owner instead of being discarded. Enabled modules are activated automatically by the supervisor during reboot restore.
- every absolute firmware address and ABI record lives in the framework's `canopus-target-private` crate; the module hardcodes no address, and the required firmware calls are intentionally not added to Canopus's generated public bindings.

Current artifact status is regenerated by `scripts/build-device.sh` (fmt, workspace + cross clippy, host tests, lean nightly cross-build, `ld.lld -r`, `.llvmbc`/debug strip, and Canopus verifier). `scripts/build-install-watchface.sh` stages it with a lifecycle-1 signed receipt. Native app publication uses the ABI 1.2 staged miwear callback; backend activation never invokes app-registry firmware calls.

The native Headphones page is published through the ABI 1.2 staged miwear callback and has passed the page-open device gate. While a page is active, a page-owner LVGL timer applies only newer semantic generations to retained row/label objects; discovery, bond, connection, stream, MTU, and error changes therefore appear automatically without destroying the content root or resetting scroll position. Manual Refresh remains a valid forced synchronization even when its row was rendered before the latest Bluetooth callback.

What remains **device-gated** is the revised end-to-end radio path: target-only bond removal confirmation, fresh SSP/link-key/encryption completion, outbound signaling and media PSM `0x0019` channels, AVDTP negotiation, test-tone playback, disconnect, and reconnect on firmware `3.101.030`. Host success and verifier-clean ELFs are not substitutes for those on-device gates.

The instruction-level firmware call order, ABI contracts, deliberate safety extensions, and remaining device gates are recorded in [`FIRMWARE_PARITY.md`](FIRMWARE_PARITY.md).

## Build

```sh
cargo test --workspace
scripts/build-device.sh
```

The cross-build runs on the **nightly** toolchain (`cargo +nightly`), which must be installed (`rustup toolchain install nightly`). The cross-binary is kept under the 64 KiB loader limit with two levers:

- `-C symbol-mangling-version=hashed` (needs `-Z unstable-options`) shrinks the long Rust symbol/section names that dominate `.symtab`/`.strtab`;
- `-Z function-sections=no` merges the ~890 per-function sections, collapsing `.shstrtab` and the section headers.

`RUSTFLAGS` replaces the `[target.*]` flags in `.cargo/config.toml`, so the scripts repeat `-C panic=abort -C target-cpu=cortex-m33`. After `ld.lld -r`, `rust-objcopy --remove-section=.llvmbc --strip-debug` drops the unconsumed thin-LTO bitcode and debug metadata. Override the toolchain with `NIGHTLY_CARGO`, the objcopy binary with `RUST_OBJCOPY`, and the framework root with `CANOPUS_ROOT`.

Dependencies are local paths into `/Volumes/EXT0/Canopus/sdk/rust`.

## Install on device (watchface)

The module is packaged as a one-shot installer watchface using the Canopus
“install watchface” concept (see `watchfaces/canopus_hello` in the framework).

```sh
scripts/build-install-watchface.sh
```

This cross-builds the module, runs the Canopus ELF verifier, signs the CMI1
receipt with the local dev key, smoke-tests the Lua installer, and stages the
payloads into `watchfaces/bluetooth-audio/`:

```text
watchfaces/bluetooth-audio/
├── main.lua       one-shot installer (opening the watchface installs the module)
├── module.bin     verified zero-import ELF32 ET_REL (gitignored)
└── receipt.bin    signed CMI1 receipt for token `bluetooth_audio` (gitignored)
```

Device steps (after the Canopus supervisor + Manager are installed via the
framework's `canopus-installer` watchface):

1. Install `watchfaces/bluetooth-audio` as a normal watchface.
2. Open it once. The supervisor verifies the Ed25519 signature, exact target
   and firmware identity, artifact size, and SHA-256, then registers the
   module as installed and disabled.
3. Open Canopus Manager and enable the `bluetooth_audio` module, then reboot and
   LOAD the supervisor. Restore loads and activates enabled modules automatically;
   Manager subsequently shows ACTIVE/BOOT_RESIDENT or the retained activation
   error. A package previously built with lifecycle 0 must be removed and
   reinstalled; replacing only its ELF leaves the persisted receipt metadata
   inconsistent.

Automatic activation starts only the identity-guarded Bluetooth/SDP backend and
marks the module boot-resident (unload then requires a reboot). The Canopus
installer then uses three separate **INSTALL** callbacks: Manager registration,
ABI 1.2 app/page registration, and Launcher publication. Publication errors are
retained in the registry and shown as a module error when Manager is opened.
Crash-free activation, both publication stages, discovery, pairing, connection,
and test tone remain device gates on firmware `3.101.030`.
